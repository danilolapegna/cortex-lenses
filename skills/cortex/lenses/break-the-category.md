# Break the Category

Release possibilities hidden by an inherited category.

## Steps

1. Name the category assigned to the object or service.
2. List useful properties that the label hides.
3. Give it three different roles without changing those properties.
4. Describe a working use for one role under the actual constraints.

## Use it when

A label determines the solution before the functions are examined.

## Leave it out when

The category is a binding technical definition that the proposal must satisfy.
